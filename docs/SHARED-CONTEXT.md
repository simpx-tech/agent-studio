# Shared account context

A separate account profile created with **Add account** uses **this computer's CLI context** by default: the same directory the terminal and desktop app use (`~/.claude` or `~/.codex`, or the managed WSL distribution's home equivalent), so its instructions, rules, skills and project memories are available without a terminal-login connection existing in Connections. Context belongs to that directory, not to the signed-in account, so switching the terminal's login does not change it. Open **Connections → Manage account → Shared context source** to choose another account connection on the same execution environment instead, or **This account only** to keep the profile separate (stored as `sharedContext: "none"`). Detected terminal logins already are the computer context, so Manage account shows **This computer's CLI context** selected for them. Choosing **This account only** on a terminal login turns that connection into a separate profile for the same account: it gets its own directory and sign-in (opened automatically after saving), keeps no shared context, and existing chats continue through native history transfer from the terminal directory, which itself stays signed in and untouched. The converted connection is marked as coming from the terminal login and, like any account of that agent connected there, keeps detection from registering that login again as another label, even for Codex, whose CLI reports no account identity. Save applies to the next reply and survives reload, workspace export, and relay sync. The source cannot itself use another shared source; cross-provider and cross-environment references are rejected by the execution host. Missing sources produce a recoverable context error without breaking sign-in or account usage.

## Linked Claude profiles

A separate Claude profile that uses this computer's CLI context is linked to that directory, so it shares everything with the Claude app and the terminal except its account (requested 2026-10-06). Its `settings.json`, `CLAUDE.md`, `rules/`, `projects/` (project memories and session transcripts), `file-history/`, `tasks/`, `plans/`, `todos/`, `plugins/`, `skills/`, `agents/`, `commands/` and `output-styles/` are symbolic links into `~/.claude` (the managed WSL distribution's own `~/.claude` for a WSL profile, or `CLAUDE_CONFIG_DIR` where that is set). Claude Code loads them natively, and a change made in one app reaches the others on their next reply: permissions, hooks, environment, enabled plugins, memories, instructions and checkpoints alike. The profile keeps only what belongs to its account: `.credentials.json` (its login and MCP sign-ins), `.claude.json` (account state, and MCP servers it added before it was linked), organization policy files and runtime state. An OAuth MCP server is therefore authorized once per account.

Agent Studio links a profile before any of its CLIs start: `src-tauri/src/linking.rs` on Windows, macOS and Linux hosts, and `src-tauri/src/wsl-share.sh` inside a WSL distribution at each launch. Linking a profile that already holds such files moves them into the shared directory first and never replaces anything there: an identical copy is dropped, and a copy that differs stays in the profile's `before-sharing` folder. Files move only on the first attempt in each run of the app, before any CLI of that run uses the profile; a later attempt links only a profile with nothing to move, and otherwise asks for a restart. Shared folders missing from `~/.claude` are created empty.

On Windows the folders are directory junctions, which Windows allows without any permission (requested 2026-10-06). The two files need symbolic links, which Windows creates only with Developer Mode on or for an administrator. So the first time a profile needs them in a run of the app, Agent Studio asks Windows once, for every account that needs them, to run its own program elevated as a small helper (`agent-studio.exe --share-claude-files`). The helper accepts connection ids only, finds each profile in this app's data itself, refuses any folder on the way that is a link, links only to a real folder inside the user's own profile, creates those two links and exits; Agent Studio itself keeps running as the user. A declined prompt is not shown again by itself in that run: until **Allow** in Connections asks again, `settings.json` and `CLAUDE.md` stay the account's own, while `CLAUDE.md` still reaches its chats as a reference, and Connections and Model context say so. With Developer Mode on, no prompt is needed.

A linked profile receives no instruction references, plugin directory or memory override, since Claude Code reads them through the links. Model context reads its files from the shared directory, because Windows cannot follow a link inside WSL through `\\wsl.localhost`. MCP server definitions in the `.claude.json` beside the shared directory still reach it through `--mcp-config`, and a server added from **Model context → MCPs** is saved there by this computer's own CLI, where the Claude app and the terminal find it. Installing, enabling or removing a plugin from **Model context → Plugins** is likewise done by that directory's own CLI, so the paths it records are the directory's. Switching a chat between two linked accounts resumes the same transcript in place, and chat import lists their transcripts once, from the computer's own source.

## Shared sources

Codex profiles, profiles that use another account as their source, and Claude profiles that are not linked yet share context without links. Sharing uses the source files in place, so later edits remain available without copying them between profiles. Agent Studio supplies host-local references to source instructions and relevant memory entrypoints, which the model reads through its normal tools. These supplement project and conversation instructions. Model context labels these references separately; discovery does not claim the model has read them.

- Codex uses the source profile's `AGENTS.override.md` (or `AGENTS.md`), `memories/memory_summary.md`, `memories/MEMORY.md`, and local `skills/` as an additional native skill root.
- Claude uses the source profile's `CLAUDE.md`, bounded `rules/*.md` discovery, and local `skills/` and `commands/` through native plugin-directory discovery. Rules keep their applicable path conditions. Its automatic memory directory uses the source's configured absolute `autoMemoryDirectory`, or the source's memory directory for the selected project. A disabled source auto-memory setting supplies no shared memory override. A custom `~/` directory currently requires conversion to an absolute path.
- MCP server definitions are shared as well. Claude receives the source's user-scope servers and the local-scope servers recorded for the selected folder from the source's `.claude.json` (the file beside the default directory, or inside a custom one) through `--mcp-config`, merged with the app's own `agent_studio` server, which keeps its name. Codex receives the source's `[mcp_servers.*]` tables from `config.toml` as `-c` launch overrides. Only definitions travel: sign-in state for remote servers stays with each profile, so a separate profile authorizes such a server once through the MCPs tab. Definitions are handed to the launched process only, never persisted, exported, relayed or serialized into process identities; bounded names and a digest represent them there. Shared definitions above the launch limit (64 servers or 24 KB) fail with an explicit message.

For these profiles, logins, credentials, MCP sign-ins, installed marketplace plugins, account settings, and cloud account memory remain account-specific. This feature shares local CLI context; it does not synchronize ChatGPT's account memories. Claude's shared automatic-memory directory becomes the chat's native memory destination; Codex receives guidance to use the source memory location when the user authorizes saving memories. Setup itself never writes source instructions or memories.

Changing the source invalidates context inventories and parked-process reuse for the affected account. The next reply resumes the conversation's native session with current shared guidance. Removing sharing stops new source guidance and tells the model that prior shared instructions are historical; it cannot erase content already present in the native transcript. Restricted background title and usage requests never inherit sharing.

Validation: Rust tests cover source scope, cycles, metadata boundaries, WSL path conversion, source memory settings, and transcript validation, paginated ancestry, retained imports, and temporary snapshot cleanup. Browser tests cover explicit selection, cancellation, persistence, removal, and layout. `scripts/account-context-probe.mjs` checks installed Codex cross-profile forking, paginated ancestry, restart continuity, and Claude shared-skill discovery without model turns. `scripts/account-context-native-smoke.mjs` drives an isolated native app through real Claude/Codex tool-result recall and A → B → A connection switching; those two connection identities use the same existing login, so that test does not prove distinct billing identities. Native WSL execution and paired Viewer transfer require separate live verification.

Native checks passed on Windows with GPT-5.6-Sol and Sonnet: the `switch` phase preserved tool-only values after file removal and account round trips; the `compact` phase preserved another tool-only value through native compaction and account switching. The `shared` phase verified real replies reading source instructions, memories, and skills, followed by discovery without those sources after disabling sharing. Run `shared` with `STUDIO_QA_DATA` pointing to the isolated app's data directory; when a packaged caller redirects AppData, `STUDIO_QA_WSL=Ubuntu` writes only the synthetic QA source files through that distribution to physical Windows storage. Reports and screenshots stay under ignored `artifacts/account-context/`. These tests do not copy credentials or change the user's normal app settings.

A separate Windows CLI check also passed with distinct signed-in accounts for both providers. It transferred only these QA transcripts into existing authenticated profiles, recalled the compacted context in a real model reply, and verified that source bytes stayed unchanged. Codex's first attempt exposed `invalid paginated history lineage ... missing source rollout`: a fork file refers to ancestors, so deleting temporary imports breaks later resume. The implementation now retains the verified ancestor prefixes, and the no-model probe reproduces the missing-ancestor failure before verifying transfer and restart with the complete lineage. Account metadata was used only in memory to establish distinct identities; reports contain booleans, not account details or credentials.
