# Notifications

On Windows, Linux, and macOS, native notification cards and the Agent Studio chime are **enabled by default**. Open **Settings → Notifications** to send a test, disable alerts, or uncheck **Play the Agent Studio chime** to keep banners without sound. Preferences apply to this installation and survive app restarts, independently of relay pairing and workspace exports. Updating the app preserves an existing Disable or Mute choice; installations without saved preferences start enabled.

Alerts cover finished replies, stopped/failed runs, and explicit parent question-tool events. Questions in ordinary text are covered when the reply finishes. A Claude reply that waits for background tests or builds the model declared finishes only after the model has reported them, not when its turn ends; servers left running for the user never delay it (see [NATIVE-SESSIONS.md](NATIVE-SESSIONS.md#waiting-for-background-work)). Local and synchronized conversations use the same lifecycle tracking. Startup history, replayed checkpoints, title changes, and child-agent questions do not generate extra alerts.

Each alert is titled with its chat's title (the start of the first message until a title is generated) and says what the reply did:

- **Finished:** the start of the final answer, or of a proposed plan when that is the answer.
- **Stopped:** `Stopped:` and the text the reply had reached, from its answer or its latest progress comment. Agent Studio's own notices about starting a session are skipped.
- **Failed:** `Failed:` and the error shown in the chat.
- **Waiting for you:** `Question:` and the question, or the name of the MCP server requesting input.

`chatNotification` in `src/lib/notifications.ts` builds this text for desktop and phone alerts alike. It reads Markdown as one plain line (code blocks, comments and visualization markers dropped; link targets, HTML tags and emphasis markers removed; headings, list items and table rows joined with separators) and cuts it at a word: titles hold at most 80 characters and the line 180. Replies without such text, such as a question tool that recorded no question, use a generic line for their kind. Account labels and CLI data never appear.

The chat you are viewing in a visible, focused window stays quiet: its lifecycle events do not show a desktop card or play the chime. Other chats still notify while you read or type, and the selected chat notifies when the window is hidden, unfocused, or showing Connections or Settings. Suppressed events are consumed without replay when you leave. Completing work does not switch the open chat or discard its draft. Test notifications remain available. OS notification/Focus settings still control card presentation.

Connected desktop and browser windows also report their foreground chat to the relay, which suppresses that chat's PWA pushes across the workspace before sending them to a push service. Viewing records are revisioned per window, kept only in memory, refreshed every five seconds, and expire after 15 seconds without an update. Blur, hiding, leaving the chat, or closing the page clears the record; expired browser sessions cannot suppress alerts. Pending retries are checked again before delivery. An already accepted push cannot be recalled, and each push that reaches the service worker still displays an alert. This requires updating both the app and relay.

The badge beside **Conversations** and the app-icon badge count **all Active chats that are not working**. Completed, failed, stopped, and saved idle chats count; running replies and History chats do not. Opening or reading a chat, searching, or choosing the History tab leaves the total unchanged. Sending a new reply removes that chat from the count until it stops working; archiving/deleting removes it. Zero hides the sidebar badge and clears the app-icon badge. The Active/History tab totals retain their existing meaning. Desktop startup still moves saved chats to History, so the badge starts at zero after that migration.

Windows uses a numbered taskbar overlay, capped visually at **99+**; macOS uses its Dock badge, and Linux uses the desktop's supported launcher badge service. The sidebar always shows the exact total. Installed PWAs use the Badging API where the browser/launcher supports it; support and notification permission vary by device. A mobile push carries the current relay count, including terminal jobs whose final workspace checkpoint has not arrived yet, and the worker applies that total even with no app page open. Retries use the latest count instead of incrementing the number of notifications. A closed PWA receives badge updates with its next lifecycle push; opening/syncing refreshes it after changes such as archiving. No extra notifications are sent solely to change a badge. Badge counts are independent of the app's chime/mute preference.

Keep Agent Studio open or minimized. Closing the desktop app still closes it; this feature does not install a background service. Clicking an alert brings the running app forward and opens its chat when available; an unsent draft stays with the chat it was typed in. Mobile push remains separate: see [MOBILE.md](MOBILE.md). Mobile browser push sounds are controlled by the phone OS; the custom chime applies to native desktop apps.

Windows uses an explicit silent WinRT toast. Linux sends the freedesktop `suppress-sound` hint. macOS uses `UNUserNotificationCenter` with no notification sound attached and requests authorization before the first alert (or when manually enabling alerts). macOS remembers the answer; after a denial, allow Agent Studio in System Settings and send a test. The bundled PCM chime plays through WASAPI, ALSA, or CoreAudio alongside the native card. No user system sound is replaced and there is no fallback to the default ding. Near-simultaneous alerts share one chime. Missing audio outputs and delivery failures appear in Settings without interrupting agent work.

Install/run the packaged app on macOS 11 or newer so it has its own bundle identity. The bundle minimum matches the modern notification backend and its foreground banner presentation. Allow Agent Studio in the system's notification settings. Linux needs a desktop notification service and audio output; its server must honor the standard suppression hint. Banners follow OS notification/Focus settings. The custom chime uses application audio, so mute it in Settings (or mute the app/system audio) during quiet periods.

Implementation: `desktop-notifications.json` in the native app's local data directory stores preferences and a bounded list of run receipts. Receipt persistence prevents repeats after renderer reloads; it holds no alert text. A notice crossing the transport carries its kind, UUID identities, and the prepared title and line. The native side rejects oversized text and text on test notices, then removes control characters and noncharacters that toast XML cannot hold and falls back to the generic text when nothing remains. The Windows toast library escapes XML itself; Linux escapes `&`, `<` and `>` when the notification server renders body markup. Windows keeps delivered alerts in Notification Center until you dismiss them. The original, embedded `src-tauri/sounds/agent-chime.wav` is reproducible with `node scripts/generate-notification-chime.mjs`; no external samples or runtime downloads are used. Linux build environments also need ALSA development headers (`libasound2-dev` on Debian/Ubuntu).
