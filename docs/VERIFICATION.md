## Site marks on links — 2026-09-26

The user asked for link rendering like Codex's: the linked site's own icon before the link text. Links in replies, reasoning, progress comments and proposed plans now open with a mark, and the link itself is medium weight in the accent color with its underline only on hover. `siteLink` in `src/lib/link-marks.ts` gives every address a browser would open as a page one class per site, 500 at a time, and the Marked link renderer in `markdown.ts` emits `<a href><span class="link-mark site-N"></span>text</a>`; every other address, and anything Marked itself rejects, keeps its plain anchor. `.link-mark` in `styles.css` masks a globe in the link's own color, so an unread, unknown or unreachable icon still holds exactly the space the icon will take. The computer showing the reply reads each site once and a single inserted stylesheet rule (`.link-mark.site-N`) replaces the globe, so a streaming reply never walks its links again and saved history, tool activity and proposed plans are marked by the same renderer without a change in their components.

`site_icons.rs` reads the icon on that computer: `/favicon.ico` on the site's own origin and, when that serves none, the beginning of its page (256 KB) for the icons it declares, trying up to three. Only `rel` values naming an icon count, so a stylesheet or Safari's `mask-icon` is skipped, and a reading is accepted only when its first bytes are ICO, PNG, GIF, WebP, JPEG or SVG — developer.mozilla.org serves a PNG as `image/x-icon`, and the HTML many sites return for a missing icon must never become a mark. Icons are bounded at 256 KB and returned as one base64 data URL, which the window CSP (`img-src 'self' data:`) already allows. Readings stay in a process-local map (twelve hours for an icon, thirty minutes for a site without one, 500 origins with the oldest evicted) and the page reads four at a time, so a reply full of links never opens a burst of connections. Nothing about a link is stored or sent on: no workspace field, export, prompt replay or relay message carries a mark, and only the origin, never the page or its path, reaches the site. Browser clients have no source for site icons and keep the generic mark; reaching a host through the relay would need a new job method and a release.

## Quota pace and context guidance

Quota pace compares used percentage with the elapsed share of the reported window, aligned to the reading's timestamp. A five-percentage-point tolerance defines **On track**; lower readings show **Below pace**, higher readings **Ahead of pace**, and 100% **Limit reached**. Guidance includes a marker on the usage bar, projected use at reset after 5% of the window has elapsed, remaining hourly/daily allowance, and advice to ease usage when ahead. Stale, failed, missing, expired, and inconsistent readings withhold the pace classification. The guide explicitly assumes evenly spread use over the full window.

Context guidance uses actual measured room and up to five consecutive growth increments, requiring three compatible readings. It stops at missing data, changed settings/model/window, or a decrease. Room/watch/near-full/full thresholds use measured percentages; fast growth warns when about three or fewer similar exchanges would reach 80%. Draft estimates have separate warnings and never move measured context or its status. These calculations use existing readings and saved replies without extra provider queries.
