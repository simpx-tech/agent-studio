# Agent Studio

Tauri 2 desktop app with Svelte 5, TypeScript, and a static SvelteKit frontend.

- Read this file before changes. Keep UI components independent of desktop IPC; use `src/lib/transport.ts`.
- Always use the design-system `ChoicePicker.svelte` for dropdowns, including forms and management pages. Do not add native HTML `select` elements. Use its `field` variant for full-width form controls and retain keyboard navigation and accessible labels.
- Open directly in chat. Keep the sidebar compact: a small Agent Studio wordmark without a tagline, conversation search and Active/History groups, and the Plug button for Connections in the footer. The entire logo, including its mark and text, is a window drag region. Keep the small conversation and folder plus actions and Ctrl+N. Do not reintroduce Overview, Workflows, the large New conversation button, or the Personal workspace footer.
- Keep agent setup, computers, accounts, and relay management together in the Connections view, retaining the Plug icon. Always use the shared dropdown component. Opening Connections and returning through the logo or Plug button must preserve the open chat and draft.
- Organize Connections by computer. Each computer contains its environments, provider CLIs, and account connections; filter connections to that computer. Shared account labels may appear on each computer where they are connected, but never mix another computer's connections into its card. Keep naming, account setup, and relay pairing in contextual dialogs. Explain that existing CLI login shares the environment's login/settings while a separate profile uses the same CLI with independent login/settings; relay sync never copies credentials.
- The Windows app manages WSL CLIs directly; no second Agent Studio app or relay pairing inside WSL is required. Inventory uses read-only listing commands. Existing Codex/Claude logins prefer the Windows installation even for WSL folders, falling back to the selected distribution's CLI only when the Windows CLI is missing. Separate WSL account profiles stay pinned to their Linux login. Never replay a failed response or authentication error on another account. Checking or executing a WSL CLI can start that distribution.
- WSL launches pass arguments as data to fixed scripts, keep prompts on stdin, use Linux-local profile/runtime directories, and cancel the owned Linux process group as well as wsl.exe. Never terminate a whole distribution to stop a chat. Do not read or copy CLI credentials across environments.
- CLI adapters belong in `src-tauri/src/providers.rs`; translate provider JSONL into the typed events in `protocol.rs`. Never render raw CLI output as HTML or emulate a terminal.
- Authentication belongs to the installed CLIs. Never read, copy, or persist their tokens. Prompts go through stdin; do not interpolate user input into shell commands.
- Usage readers use read-only CLI queries. Missing limits are unknown, not zero; preserve stale readings on failures. Claude Fable limits come from server-labelled model scopes and appear only for Fable. The main context meter uses the latest compatible reply's provider-reported request count (`contextInput`), never turn totals or draft estimates. Unmeasured context stays unknown. Serialize frontend builds and browser checks against the reused Vite server, since build-generated files can reload test pages.
- Model context inspection is a separate file inventory scoped to the selected model, connection, execution environment, and folder. Route it through transport to the owning host and preserve Windows-first/isolated-WSL selection. Distinguish CLI-reported metadata from discovered, disabled, overridden, and companion guidance; never claim a startup query is a previous reply's read history. Return only file metadata, never configuration bodies, credentials, or memory contents. Keep inspection out of persisted conversations. Use stable selection values and untracked transport calls in Svelte effects so relay polling cannot restart inspection.
- Reopening Model context shows its latest cached inventory immediately while refreshing. Keep cache keys specific to provider, model, connection, computer, environment, and folder; share pending requests for the same selection. Preserve the last result and its timestamp on refresh failure. Cache only bounded session metadata, with no persistence into conversation storage.
- Claude and Codex conversations enable all built-in tools and load the selected CLI profile's configured integrations, skills, and project guidance. Chat tool calls run with full access and without approval prompts, as requested by the user. The selected folder is the CLI working directory. Background title generation and usage queries remain restricted; Gemini retains its enforced conversation-only mode. Keep the account-line hover description accurate about the selected provider's tool access.
- Codex chat uses ephemeral app-server threads so sub-agent lifecycle, child results, and tool events reach the UI; restricted titles still use exec. Keep the validated process working directory, profile isolation, stdin requests, and owned process-tree cancellation. Tool activity is bounded, typed metadata stored additively in activity blocks and updated by identity/revision through local runs, relay delivery, and checkpoints. Keep child text/usage out of the main reply. Distinguish available skills from actual skill invocations or observed file reads; adding a skill to the composer does not claim it loaded. Never expose raw command output, arbitrary tool arguments, or skill/configuration bodies in activity cards. Show unconfirmed outcomes after missing completion instead of inventing success.
- Show progress text and tool activity inline while a reply runs. On completion, show the final answer followed by a collapsed, expandable summary with tool-call, web-search, sub-agent, and command-run counts and filters. Searches and command runs are subsets of recorded tool calls; count children by identity, not lifecycle updates. Keep intermediate progress separate from the final answer and prompt replay, and retain it through saved history and relay updates. Tool headers must identify their file, pattern, query, or description when reported; details show allowlisted targets, line ranges, match counts/paths, returned tool names, and command exit metadata. Missing metadata gets an explicit explanation, never an empty disclosure or fabricated target.
- Quota pace compares usage with an even-use guide at the reading's timestamp; stale, failed, missing, or expired readings have no pace classification. Context growth uses consecutive compatible measured request counts, stops at gaps/model changes/decreases, and never treats draft forecasts as measured usage.
- Keep usage UI concise: show current numbers, resets, budgets, and actionable warnings. Do not show a next-request estimate or Details section. Use colored trend arrows with hover descriptions and accessible names for limits: On track is blue/right, Below pace green/downward trend, Ahead of pace amber/upward trend, and exhausted limits red/upward trend. Unknown pace uses a gray dash; quota bars match the indicators. Context shows its value without a Reported label or arrow; retain its hover guidance and expanded warnings.
- Place Usage and context directly below the message input, replacing the Tools enabled caption. Show exactly three compact usage groups for Context, 5-hour, and Weekly, with unknown readings visibly distinct from zero. Clicking a bar opens the reset/budget/guidance panel above the input; retain Fable's additional scoped limit there. Keep automatic refresh and keyboard expansion/closing, but no refresh or gauge buttons. Vertically center the panel title and Checked text with Close. Overlay the current quota fill and a neutral recommendation on the same track and percentage scale, keeping the recommendation endpoint visible when current usage passes it. Do not show a Recommended label or separate guide row; retain the comparison in hover and accessible text. Use the existing timestamp-based even-use guide; hide it when stale, failed, expired, or unknown, and do not invent a timed context recommendation. Keep tool-access information in the account-line hover description. Do not restore the usage strip above the chat.
- Persist portable agent and conversation data through the versioned schema. Surface storage failures. Keep credentials out of exports and tests.
- Workspace v3 separates computers, environments, account labels, and CLI connections. Installation identity and sync checkpoints are local. Never route a missing/offline connection to a different account; profile scope must cover detection, sign-in, models, usage, titles, and chat.
- New conversations select a computer and then a folder. Folder paths belong to a specific environment and owning computer; keep that location and connection identity stable while existing WSL logins use Windows-first CLI resolution. Browse only directory names through transport on the owning host. Windows CLIs access a selected WSL folder through its translated Windows/UNC path; Linux fallback uses the original Linux path. Fail if the same folder is unavailable or cannot be represented on Windows; never silently substitute the app runtime or another computer. Apply the provider-specific chat tool access policy. Generate application-owned agent definitions/hooks only in app data, never in the selected project. Legacy chats without a folder and title generation retain the isolated runtime. Keep Active and History sections grouped by computer then folder. On app startup, move all saved chats to History without changing their messages, settings, or recency. History chats allow typing and next-reply settings immediately; sending a valid message automatically restores the same chat to Active. Opening, typing, empty submissions, and blocked sends must not restore it. Preserve location/archive metadata in storage and relay conflict handling, including one-sided archive changes concurrent with response checkpoints.
- Keep Computer, Folder, Agent, Model, and Reasoning inline in one chat toolbar with decorative laptop, folder, bot, chip, and brain icons inside their dropdown triggers. Multiple account connections belong in the Agent picker; do not add a separate Run on row. Show the full folder path only as a hover title in the toolbar and folder choices. The top bar shows only the current page/conversation title, with no Workspace breadcrumb, Local desktop badge, or version text.
- Reselecting the current computer or folder is a no-op and preserves the draft. Apply validated folders without awaiting CLI detection or relay sync. Reuse connection availability within an environment and cache model catalogs per provider/connection; keep Model usable during refresh. Unknown local CLIs may be configured while checking, but sending still requires detected availability. Late checks must never replace newer folder, conversation, or explicit agent/model/reasoning choices.
- Computer, Folder, and Agent (including its account connection) are fixed once a conversation exists, starting with its first submitted message. Lock their controls and mutation handlers for existing, restored, and legacy conversations. A new blank conversation can choose all three. Model and Reasoning remain editable while a reply runs and apply to the next submitted message, with a small pending hint and a switch notice before the affected reply. Instructions remain editable between replies. Preserve in-flight and historical reply settings, including during relay checkpoints; concurrent deliberate settings edits still require conflict copies.
- Reply headings show the captured or provider-reported model name, rather than the provider or a former preset name. Keep the CLI/account/computer execution subtitle hidden. Save the model display name with each reply so catalog or conversation changes cannot relabel history; an unreported default remains explicitly unknown as CLI default.
- The conversation sidebar uses Active and History tabs with counts, then muted computer headings, collapsible folder groups indented one level under their computer (including No folder), and readable conversation rows. Its right divider supports dragging and keyboard resizing, remembers the width locally, and leaves room for the chat area when the window shrinks. Avoid stacked status accordions, repeated conversation icons, or tree guide lines. Keep tab keyboard navigation, folder hover paths, running indicators, and current-conversation semantics. Archive/restore reveals the destination tab and folder; switching tabs does not change the open conversation.
- Each sidebar computer and folder, including No folder, has a New conversation action in Active and History, even when collapsed. The computer action starts a fresh Active draft on that computer with folder selection available. Folder actions retain the exact computer, environment, and path; No folder starts without a project folder using that environment's isolated runtime. Pick a compatible CLI using the usual remembered model/reasoning choices and focus the composer. Never inherit the old conversation's messages or archive state, parse the folder identity from a display name, or fall back to the local computer when the selected one is offline. Disable actions whose owning computer or environment cannot be identified.
- Relay connections use HTTPS except on loopback, keep the pairing key in native memory, and never forward provider credentials. Preserve revision checks, deletion baselines, same-run reconciliation, and conflict copies. In-flight remote work is not automatically replayed after disconnection or relay restart. The execution host must retain response checkpoints.
- Keep Vite from watching artifacts, test-results, and relay data. On Windows, use a separate Cargo target directory and Tauri identifier for native QA when a running app locks the normal debug executable; never terminate the user's active app to unblock a test build. Complete native builds before browser checks as well; concurrent compilation can exhaust the browser startup timeout.
- Pace arrows are bare 16px icons matching the app's usual stroke weight. Do not add borders, colored backgrounds, or badge containers around them.
- Keep the reply token/time row above the completed activity summary, readable at 11px and wrapping on narrow windows. Make it expandable with a usage breakdown and provider-reported estimated cost in USD. Missing cost stays unknown, including older replies; never infer charges from subscription limits. Preserve reported cost through saved history and relay. Do not add a copy-response action to that row.
- Show cumulative total AI time through each reply alongside its own elapsed time. Derive it from recorded durations of this and earlier saved assistant replies in the same conversation, including stopped/failed replies. Exclude user messages and running replies; mark totals with missing timing as incomplete and do not add nested tool or child-agent time again.
- Configure provider, model, reasoning, and instructions per conversation; do not reintroduce the preset agent library. Remember models per provider and reasoning per provider/model. Preserve each reply's settings when later model, reasoning, or instruction choices change. Workspace v2 migrates v1 and retains the original desktop file as a backup on first save.
- Validate changes with `npm run verify`, `cargo fmt --manifest-path src-tauri/Cargo.toml --check`, `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings`, and `cargo test --manifest-path src-tauri/Cargo.toml`.
